## 1. 项目背景与目标

### 1.1 项目背景

在进行游戏画面自动化测试时，需要大量标注游戏 UI 元素（如按钮、图标、技能冷却框、血条等）的目标检测数据集。目前市面上的通用标注工具（如 LabelImg、CVAT）功能冗余、操作流程与游戏 UI 标注场景不太匹配，且不支持针对游戏画面的专属优化。

### 1.2 项目目标

开发一个轻量、高效、专为游戏 UI 标注场景设计的本地 Web 标注工具。

- **核心功能**：支持矩形、正方形、椭圆、圆形四种形状的灵活标注。
- **格式兼容**：导出标准 YOLO 格式（TXT），可直接用于 YOLO 模型训练。
- **UI 原语策略**：形状信息通过类别命名约定编码（如 `Btn_Circle`、`Btn_Rect`），YOLO 模型推理时返回 class name 即包含形状信息，脚本取 bbox 中心点即为可点击坐标。
- **操作便捷**：提供游戏 UI 标注专属的快捷操作和视觉辅助。
- **工作模式**：批量处理——用户准备好图片集后一次性加载，逐一标注完成。

### 1.3 使用场景

1. 用户准备好一套游戏截图
2. 在工具中创建项目，加载图片文件夹
3. 逐张标注 UI 元素（按钮、图标、血条等），类别名编码形状信息
4. 标注完成后 `labels/` 目录直接用于 YOLO 训练
5. 训练好的 YOLO 模型推理 → 返回 class name + bbox → 脚本根据 class name 中的形状信息计算点击坐标

```

[用户点击"浏览"] → 前端调用 Tauri IPC invoke
    → Rust 打开原生文件/目录选择对话框

    → 发送给 Django API 创建项目
```

### 2.5 设计原则

- **桌面原生**：Tauri 壳提供原生窗口、文件对话框、系统托盘，解决浏览器沙箱限制
- **轻量**：纯本地运行，无需数据库，文件系统存储所有数据。安装包 ~15 MB
- **零配置启动**：用户双击桌面图标即可使用，Django 后端自动静默启动和停止
- **即时保存**：每次标注操作自动写入 TXT 文件，随时可用于 YOLO 训练
- **形状即类别**：形状信息编码在类别命名中，YOLO 训练和推理自然携带
- **简单优先**：不支持 resize、框选等复杂操作，删除重画即可

## 3. 数据模型与格式规范

### 3.1 类别配置 (classes.json)

用户在项目根目录放置此文件，工具启动时自动加载。支持不同项目切换不同类别集。

**核心约定——形状编码在类别名中**：类别名应包含形状信息，YOLO 训练后可通过 class name 获知形状。推荐命名规范：`{类别}_{形状}`。

```json
{
  "classes": [
    {"id": 0, "name": "Btn_Circle",    "color": "#FF4444"},
    {"id": 1, "name": "Btn_Rect",      "color": "#FF6666"},
    {"id": 2, "name": "Icon_Circle",   "color": "#44BB44"},
    {"id": 3, "name": "Icon_Ellipse",  "color": "#66DD66"},
    {"id": 4, "name": "HP_Bar",        "color": "#4444FF"},
    {"id": 5, "name": "Skill_CD",      "color": "#FFAA00"}
  ]
}
```

**字段说明**：
- `id`：类别编号，从 0 开始，对应 YOLO 格式中的 class_id
- `name`：类别名称，建议编码形状信息
- `color`：标注框显示颜色（十六进制），用于 Canvas 渲染

**YOLO 推理后的使用方式**：
```
模型返回: class="Btn_Circle", bbox=(0.52, 0.31, 0.09, 0.09)
脚本解析:
  - 形状: "Circle" (从 class name 提取)
  - 点击坐标: bbox 中心 = (0.52, 0.31)
  - 后续结合 OCR 判断按钮身份和状态
```

### 3.2 YOLO TXT 标注文件

每张图片对应一个同名 `.txt` 文件，存放在 `labels/` 目录。每次标注操作后自动保存。

**格式**：每行一个标注，空格分隔：
```
class_id x_center y_center width height
```

**坐标规则**：
- 所有值均为归一化值（0~1 之间），保留 6 位小数
- `x_center`, `y_center`：外接矩形中心点坐标
- `width`, `height`：外接矩形宽高
- 所有形状（矩形、正方形、椭圆、圆形）统一取外接矩形转换为此格式

**示例** (`screenshot_001.txt`)：
```
0 0.523438 0.312500 0.089063 0.045185
2 0.122917 0.567593 0.034375 0.034537
4 0.750000 0.890185 0.210000 0.015000
```

### 3.3 形状元数据 (.meta/)

由于 YOLO TXT 格式只存储归一化矩形坐标，不保留用户绘制的原始形状类型（矩形/正方形/椭圆/圆形），为了断点续标时能正确恢复标注框的视觉呈现，需要在 `.meta/` 目录下存储每个标注的形状信息。

每张图片对应一个同名 `.meta.json` 文件，格式：

```json
[
  {"class_id": 0, "shape": "circle"},
  {"class_id": 2, "shape": "ellipse"},
  {"class_id": 4, "shape": "rect"}
]
```

**注意**：`.meta/` 仅为工具内部使用（断点续标时恢复标注显示），不是导出给用户的。用户只需要 `labels/*.txt` 用于 YOLO 训练。

## 4. Canvas 交互模型

### 4.1 工具模式

工具栏提供 5 种模式，同一时间只有一种激活：

| 模式 | 快捷键 | 光标样式 | 行为 |
|------|--------|----------|------|
| 矩形 | `1` | 十字 `+` | 对角拖拽画矩形 |
| 正方形 | `2` | 十字 `+` | 对角拖拽，1:1 锁定 |
| 椭圆 | `3` | 十字 `+` | 对角拖拽画内切椭圆 |
| 圆形 | `4` | 十字 `+` | 对角拖拽，1:1 锁定画内切正圆 |
| 选择/移动 | `S` | 默认箭头 | 点击选中标注框，拖拽移动位置 |

当前激活的工具在底部工具栏以高亮状态显示。

### 4.2 绘制流程

```
mousedown → 记录起点 (x1, y1)，开始实时预览
mousemove → 从 (x1, y1) 到当前鼠标位置的动态框实时渲染
mouseup   → 确认最终框，加入标注列表，自动保存 TXT + meta
```

**各形状绘制逻辑**：
- **矩形**：以 (x1,y1) 和 (mouseX,mouseY) 为对角的矩形
- **正方形**：以 max(|dx|, |dy|) 为边长，从起点向鼠标所在象限延伸
- **椭圆**：以 (x1,y1) 和 (mouseX,mouseY) 为对角的矩形的内切椭圆
- **圆形**：以 max(|dx|, |dy|) 为直径，从起点向鼠标所在象限延伸的正圆

**交互细节**：
- 拖拽方向任意（左上→右下、右下→左上等均可）
- 绘制可视化反馈：拖拽中的框用虚线显示，确认后变为实线
- 最小标注尺寸：3px，小于此值不创建标注（防误触）
- 绘制过程中按住 `Shift` 可临时切换正方形↔矩形、圆形↔椭圆

### 4.3 选择与移动

- 切换到选择模式（`S` 键），点击任意标注框内部区域即选中
- 选中后显示高亮边框（线宽加粗 2px → 4px，颜色为该类别颜色）
- 选中后可拖拽移动整个框
- 点击空白区域取消选中
- 重叠框处理：点击区域有多个框时，最后创建的优先选中；再次点击同一位置循环切换至下一个
- 选中框的属性在右侧属性面板中显示

### 4.4 删除

- 选中标注框后，按 `Delete` 键删除
- 删除操作可撤销（Ctrl+Z）
- 也可在属性面板中点击"删除"按钮

### 4.5 缩放与平移

| 操作 | 行为 | 备注 |
|------|------|------|
| `Ctrl+滚轮` | 缩放 | 以鼠标位置为中心缩放 |
| `右键拖拽` | 平移画布 | 任意模式下均可用 |
| `双击空白区域` | 自适应窗口 | 图片缩放到刚好适合当前视口 |
| `0` | 重置为 100% | 恢复原始像素大小 |
| 缩放范围 | 10% ~ 500% | 超出范围停止缩放 |

**坐标系统保证**：缩放和平移仅改变视图变换矩阵，不影响标注坐标。所有标注坐标始终基于原始图片分辨率。

### 4.6 十字准星辅助线

- 显示在图片正中心，贯穿画布的水平和垂直半透明线
- 默认开启，按 `H` 键切换显示/隐藏
- 始终跟随图片坐标系（缩放时保持指向图片中心，而非视口中心）
- 纯视觉参考，无吸附功能
- 线型：`rgba(255, 255, 255, 0.3)`，线宽 1px，虚线（短划线 8px / 间隔 8px）

## 6. 标注生命周期与撤销重做

### 6.1 状态机

```
[空闲] ──按1-4选工具──→ [绘制模式]
  └── mousedown ──→ [拖拽中] ──mouseup──→ [标注创建]
                                           └── 自动保存 TXT + meta
                                           └── 压入 undo 栈
                                           └── 返回 [空闲]

[空闲] ──按S──→ [选择模式]
  ├── 点击框 ──→ [已选中]
  │   ├── 拖拽 ──→ [移动中] ──mouseup──→ 保存 → 压栈 → [已选中]
  │   ├── Delete ──→ 删除 → 保存 → 压栈 → [空闲]
  │   ├── 属性面板改类别 ──→ 保存 → 压栈 → [已选中]
  │   └── 点击空白 ──→ [空闲]
  └── 点击空白 ──→ 保持 [选择模式]
```

### 6.2 Undo/Redo 实现

- **操作粒度**：每次独立的标注操作（创建、移动、删除、修改类别）作为一个 undo 单元
- **Ctrl+Z**：撤销上一个操作，被撤销的操作移入 redo 栈
- **Ctrl+Y**：重做上一个被撤销的操作，从 redo 栈移回 undo 栈
- **新操作清空 redo**：撤销后如果做了新操作，redo 栈清空（标准行为）
- **Undo 栈上限**：50 步，超出时移除最旧记录
- **跨图片行为**：切换到另一张图片时，undo/redo 栈清空

### 6.3 标注 ID

每个标注在创建时分配唯一 ID，用于：
- undo/redo 栈中精确追踪操作目标
- 属性面板定位当前选中标注
- 前端内部状态管理

## 9. 图片管理

### 9.1 支持的格式

- JPEG (`.jpg`, `.jpeg`)
- PNG (`.png`)

### 9.2 排序

图片按文件名自然排序（`screenshot_001.png` < `screenshot_002.png` < `screenshot_010.png`）。

### 9.3 状态定义

| 状态 | 定义 | 图标 |
|------|------|------|
| 已审核 (reviewed) | 标注已完成且已人工审核确认 | 🟢 |
| 已标注 (annotated) | 该图片至少有 1 个标注框，待审核 | 🟡 |
| 未标注 (unannotated) | 该图片尚无标注 | ⚪ |

**审核状态切换**：在属性面板或右键菜单中提供"标记为已审核"/"取消审核"操作。也可以在标注主界面中按 `R` 键快速切换当前图片的审核状态。审核状态存储在 `.meta/<image_name>.reviewed.json` 中（独立于标注数据，避免 TXT 修改影响审核标记）。

### 9.4 切图行为

- 按 `A` / `←` 切换到上一张图片
- 按 `D` / `→` 切换到下一张图片
- 切换前自动保存当前图片标注
- 到达第一张/最后一张时，快捷键无效（不出错、不循环）
- 也可直接点击左侧图片列表中的任意图片跳转

### 9.5 断点续标

- 打开已有项目时，自动跳转到上次标注的图片
- 已标注的图片会加载已有标注线框和形状信息
- 标注进度（已标注数/总数）实时显示在状态栏

### 9.6 导入已有 YOLO 标注

如果用户在项目 `labels/` 目录下放置了已有的 `.txt` 标注文件（预标注结果或从其他工具迁移），但没有对应的 `.meta/` 文件，工具在加载时：

- 所有标注的形状均显示为**虚线边框**，提示用户形状信息已丢失
- 属性面板中形状字段显示为"未知"（unknown）
- `.meta/` 与 TXT 标注行数不一致时，显示警告横幅并回退为矩形，同时在状态栏显示 ⚠ 图标
- 用户可在属性面板中逐个修正形状，或通过右键菜单"批量设置形状"统一修复

## 10. 错误处理与边界情况

### 10.1 错误处理策略

| 场景 | 处理方式 |
|------|----------|
| 图片加载失败 | Canvas 显示占位文字"图片加载失败"，侧边栏标记为红色 ⛔ |
| TXT 写入失败 | 在底部状态栏显示红色错误提示，不清除内存中的标注数据 |
| 类别配置文件格式错误 | 弹窗提示具体错误，回退到默认空类别列表 |
| 图片目录不存在 | 创建项目时校验，目录不存在则拒绝创建并提示 |
| 图片目录为空 | 创建项目时校验，没有图片文件则拒绝创建并提示 |
| 最小标注限制 | 绘制框小于 3px 时不创建标注，静默忽略 |
| 项目名称非法字符 | 校验项目名称，仅允许字母、数字、下划线、中文 |
| 同一图片重复创建标注框 | 允许（符合实际情况），不做去重 |

### 10.2 单实例锁

Tauri 应用配置为单实例运行——用户无法同时打开两个应用窗口。这从根本上避免了多个进程同时写入同一项目文件的数据竞争问题。单实例锁在 `tauri.conf.json` 中通过 `identifier` + Rust 侧的 `tauri::RunEvent::Ready` 实现，第二个启动尝试会自动聚焦到已有窗口。

### 10.3 平台兼容性

- Tauri WebView 在各平台使用系统原生引擎：Windows 用 WebView2（Edge Chromium），macOS 用 WKWebView
- 效果等同于 Chrome/Edge 最新版，无浏览器兼容性问题
- 支持平台：Windows 10+、macOS 11+

### 12.2 v1.0 数据完整性保障

以下措施在 Phase 1 实施阶段即应加入，而非等到 Phase 4：

#### 原子写入模式

`save_annotations` 中的所有文件写入操作遵循"先写临时文件，成功后原子 rename"模式：

```
写入 labels/screenshot_001.txt:
  1. 写入 labels/.tmp_screenshot_001.txt
  2. 写入成功后 os.rename(.tmp_... → screenshot_001.txt)
  3. 写入 .meta/.tmp_screenshot_001.meta.json
  4. 写入成功后 os.rename(.tmp_... → screenshot_001.meta.json)
```

伪代码实现：

```python
import tempfile, os

def atomic_write(path, content_func):
    """原子写入：先写同目录临时文件，成功后再 rename。"""
    tmp_path = path.parent / f".tmp_{path.name}"
    content_func(tmp_path)  # 调用方写入内容
    os.replace(tmp_path, path)  # 原子替换（Windows/Linux 均支持）
```

#### 启动时一致性检查

每次打开项目时（`project_detail` GET 或前端首次加载），自动扫描 `labels/` 与 `.meta/` 的一致性：

| 检查项 | 不一致时的处理 |
|--------|---------------|
| TXT 存在但 `.meta.json` 不存在 | 标注显示为矩形 + 虚线边框，提示用户 |
| `.meta.json` 存在但 TXT 不存在 | 删除孤立 `.meta.json` 文件（TXT 是真相源） |
| 行数不一致 | 标注回退为矩形，前端显示 ⚠ 警告横幅 |
| TXT 和 `.meta/` 均缺失但 `.reviewed.json` 存在 | 删除孤立 `.reviewed.json` |

此检查在 `labeler/utils.py` 中实现为 `verify_project_integrity(project_dir)`，在项目详情 API 被调用时自动执行，结果以 `integrity_warnings: [...]` 字段返回前端。
